VIDEO ATTRIBUTES EXPLAINED:
──────────────────────────

• loop: Video repeats continuously
• poster: Thumbnail shown while video loads (end frame with thread)

TROUBLESHOOTING GUIDE
═══════════════════════════════════════════════════════════════════

PROBLEM: Video doesn't autoplay
─────────────────────────────────
SOLUTION 1: Ensure "muted" attribute is present
The <video> tag MUST have muted for browsers to allow autoplay.

SOLUTION 2: Check browser console for errors
Open DevTools (F12) and look for error messages.

SOLUTION 3: Verify file path is correct
Test by visiting the video URL directly in your browser:
https://luis-gilberto.com/insights/assets/videos/insights-video.mp4


PROBLEM: Video shows playback controls
────────────────────────────────────────
SOLUTION: Make sure you did NOT add "controls" attribute
The <video> tag should NOT have controls attribute.


PROBLEM: Video is too slow to load
────────────────────────────────────
SOLUTION 1: The video is already optimized (230KB)
This is very small and should load quickly even on 3G.

SOLUTION 2: Check your CDN/server configuration
Ensure video is served with proper MIME type (video/mp4)

SOLUTION 3: Enable compression on server
Add gzip/brotli compression for .mp4 files in server config


PROBLEM: Video doesn't loop smoothly
──────────────────────────────────────
SOLUTION: This is already handled in the optimized video
The first and last frames match for seamless looping.

If you see a flash, clear cache and reload.


PROBLEM: Video looks pixelated/blurry
───────────────────────────────────────
SOLUTION: This is intentional for performance
The video is 1920x1080 but compressed for web.
If quality is insufficient, I can provide a higher-quality version
(but it will be larger and load slower).


PROBLEM: Mobile shows fullscreen button
─────────────────────────────────────────
SOLUTION: Ensure "playsinline" attribute is present
This prevents iOS from forcing fullscreen.


PROBLEM: Poster image doesn't appear
──────────────────────────────────────
SOLUTION: Check the poster image path
Verify: /insights/assets/videos/insights-poster.jpg exists
The poster shows while video loads (brief moment).


PROBLEM: Fallback text styling is wrong
─────────────────────────────────────────
SOLUTION: Check .insights-video-title h1 CSS
Ensure it matches your original .hero-section h1 styles.


PROBLEM: Video is sideways/wrong orientation
──────────────────────────────────────────────
SOLUTION: The optimized video is already landscape
If you see portrait orientation, you may be using the wrong file.
Use "insights-video.mp4" (the optimized version).

ACCESSIBILITY NOTES
═══════════════════════════════════════════════════════════════════

WCAG COMPLIANCE:
The implementation is accessible:

1. TEXT FALLBACK:
   The <h1>Insights</h1> inside <video> ensures screen readers
   get the text content even if video is unsupported.

2. AUTO-PLAY POLICY:
   Video is muted, so it complies with WCAG guidelines for
   auto-playing media (no unexpected audio).

3. MOTION SENSITIVITY:
   The animation is subtle and smooth. If you need to support
   users with motion sensitivity, add this CSS:

   @media (prefers-reduced-motion: reduce) {
       .insights-video-title video {
           display: none;
       }
       .insights-video-title h1 {
           display: block !important;
       }
   }

4. KEYBOARD NAVIGATION:
   Video doesn't interfere with keyboard navigation.
   Users can still tab through page elements normally.
