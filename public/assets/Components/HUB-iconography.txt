## Problem Statement

Icons are being used inconsistently across Hub pages, breaking the semantic meaning of each Hub arm. We need:

- **Single source of truth** for icon-to-service mappings
- **Strict enforcement** of which icons represent which services
- **Centralized library** preventing icon confusion
- **Clear documentation** for current and future pages

**Example violations found:**
- Advisory page using telescope instead of compass
- StrategyIQ using teal icons instead of coral
- Inconsistent icon sizes across pages
- Icons in deprecated /floating-shapes/ folder still being referenced

## Step 1: Create Icon Library Structure

### Directory Structure to Create

```

│   │   ├── compass_rose_coral@2x.png
│   │   └── compass_rose_coral.svg
│   │

│   │

│       ├── chess_queen_teal.png

│       └── chess_queen_teal.svg
│
└── deprecated/                     # Old/unused icons for reference
    └── floating-shapes/            # Move old inconsistent icons here
```

### Action Items

1. Create all directories listed above
2. Move existing icons from `/TheHub/assets/icons/floating-shapes/` into the appropriate `/arms/` subdirectories
3. Rename files to match the naming convention: `[symbol]_[color].png`
4. Create `@2x` retina versions (double resolution)
5. Create or convert to SVG versions for scalability
6. Move any unused/conflicting icons to `/deprecated/` folder

```markdown
# Hub Icon System - Usage Guidelines

## The Four Arms Icon Map

| ARM | ICON | COLOR | FILE | NEVER USE |
|-----|------|-------|------|-----------|
| **StrategyIQ** | Telescope | Coral | `telescope_coral.png` | Compass, Atom, Queen |
| **Advisory** | Compass Rose | Coral | `compass_rose_coral.png` | Telescope, Atom, Queen |
| **Studio** | Atom Model | Teal | `atom_model_teal.png` | Telescope, Compass, Queen |
| **Portal** | Chess Queen | Teal | `chess_queen_teal.png` | Telescope, Compass, Atom |

## Sacred Rules

### 1. NEVER Swap Icons
❌ **WRONG:** Using telescope for Advisory  
✅ **RIGHT:** Using compass rose for Advisory

### 2. NEVER Change Colors
❌ **WRONG:** `telescope_teal.png`  
✅ **RIGHT:** `telescope_coral.png`

### 3. ALWAYS Use Full Paths
❌ **WRONG:** `../../icons/telescope.png`  
✅ **RIGHT:** `/TheHub/assets/icons/arms/strategyiq/telescope_coral.png`

### 4. ALWAYS Include Alt Text
❌ **WRONG:** `<img src="..." alt="">`  
✅ **RIGHT:** `<img src="..." alt="StrategyIQ">`

## Where Each Icon Appears

### Telescope (StrategyIQ)
- StrategyIQ landing page hero
- Hub homepage Card 01 (Architecture grid)
- Hub homepage Flow Step 1
- All StrategyIQ marketing materials
- Assessment report covers
- Strategic brief templates

### Compass Rose (Advisory)
- Advisory landing page hero
- Hub homepage Card 02 (Architecture grid)
- Hub homepage Flow Step 2
- All Advisory marketing materials
- Consultation proposals
- Leadership alignment docs

### Atom Model (Studio)
- IMC Services landing page
- Hub homepage Card 03 (Architecture grid)
- Hub homepage Flow Step 3
- All Studio marketing materials
- Creative briefs
- Production deliverables

### Chess Queen (Portal)
- Portal login page
- Hub homepage Card 04 (Architecture grid)
- Hub homepage Flow Step 4 (highlighted with teal border)
- Portal interface elements
- Project dashboards
- Client communications

## Implementation Checklist

When adding icons to a new page:

- [ ] Import `/TheHub/assets/css/icon-system.css`
- [ ] Use component from `icon-components.html`
- [ ] Verify correct icon for the arm
```

## Troubleshooting

### Common Issues and Solutions

**Issue:** Icons not displaying  
**Solution:** Check that icon paths use absolute paths starting with `/TheHub/`

**Issue:** Wrong icon appearing  
**Solution:** Verify icon filename matches manifest.json exactly

**Issue:** Icon size inconsistent  
**Solution:** Import icon-system.css and use standard sizing classes

**Issue:** Icon color wrong (e.g., teal instead of coral)  
**Solution:** Check manifest.json for correct filename with color suffix

**Issue:** Deprecated icon still showing  
**Solution:** Search codebase for old path (e.g., `/floating-shapes/`) and replace

**Issue:** Icon not responsive on mobile  
**Solution:** Ensure icon-system.css is imported and using `.hub-icon` classes

## Maintenance Guidelines

### Adding New Pages

When creating new Hub pages:

1. Import icon-system.css in `<head>`
2. Reference icon-components.html for markup
3. Use icons from manifest.json only
4. Never create custom icon variations

### Updating Icons

If an icon needs to be updated:

1. Update the source file in `/arms/[service]/`
2. Maintain the same filename
3. Update @2x retina version
4. Update SVG version
5. No code changes needed - path remains the same

### Adding New Services

If adding a new service arm (rare):

1. Define icon symbol and meaning
2. Add entry to manifest.json
3. Create icon files in `/arms/[new-service]/`
4. Add CSS variables to icon-system.css
5. Create component examples in icon-components.html
6. Update README.md and QUICK-REFERENCE.md
7. Get approval before deploying
