
Trae Patch — Fix Contact CTA Rendering + IMC Variant (v5)
Best Option: Point CTA to root contact route + add IMC variant hooks
Author: ChatGPT for Luis Gilberto
Date: 2025-09-22

WHY THIS PATCH
--------------
The “bad-looking” contact page occurs when it is opened from a nested path (e.g., /assets/Contact/contact.html?from=imc). Relative asset paths like "styles/main.css" then resolve to /assets/Contact/styles/main.css (404). The safest, smallest fix is to always route users to the ROOT contact page so assets load correctly, and then add the IMC variant (anchor + copy swap + attribution).

FILES TO EDIT
-------------
[1] IMCServices/index.html
[2] contact.html  (root-level contact page)

---------------
Create a quick backup branch/commit before changes.

TASK 4 — Add the detection script (just before </body>)
-------------------------------------------------------
Insert this <script> block **right before** </body>:

<script>
(function(){
  var params = new URLSearchParams(location.search);
  var from = (params.get('from') || '').toLowerCase();

  // Set attribution for submissions
  var lead = document.getElementById('lead_source');
  if (lead) lead.value = from || 'organic';

  if (from === 'imc') {
    // Enable IMC variant
    document.documentElement.classList.add('from-imcservices');

    // Copy swap
    var head = document.querySelector('[data-contact-headline]');
    var sub  = document.querySelector('[data-contact-subcopy]');
    if (head) head.textContent = "Let’s scope the right engagement.";
    if (sub)  sub.textContent  = "You came from the IMC Services hub. Tell us where you are in your journey and we’ll map the smartest next step.";

    // Smooth nudge so anchor lands below sticky header
    if (location.hash === '#cta-hook') {
      var el = document.getElementById('cta-hook');
      if (el) requestAnimationFrame(function(){
        var y = el.getBoundingClientRect().top + scrollY - 96; // adjust offset to header height
        scrollTo({ top: y, behavior: 'auto' });
      });
    }
  }
})();
</script>

NOTES
-----
- This patch intentionally avoids changing asset paths; it fixes the rendering by ensuring the contact page is always loaded from root (so current relative links keep working).
- If, in the future, the contact page must be served from a nested path, switch asset URLs to root-absolute (e.g., href="/styles/main.css") or add <base href="/"> in <head> and test nav thoroughly.
